Accessibility review

review-accessibility.md

Lens: WCAG 2.2 AA on a consumer conversion surface. Critique is of the spines, not of an implementation. Live MarketingProductCarousel is cited only as behavioral ground truth.

The spines want the right floor — reduced-motion is the real carousel, not a dimmed film; pills are named; there is no autoplay; mobile does not pin — then leave the dangerous parts as [ASSUMPTION]. Desktop cinema as drawn is a sticky-on-sticky scroll machine whose only skip control leaves the viewport, whose live region will narrate the scrub, and whose inherited stone/gold pairings fail 1.4.3 on the copy and seek labels the section now depends on. Do not build until pin geometry, seek persistence, announcement policy, and control contrast/size are locked. Polish can wait; trapping Priya in 540vh of unlabeled progress cannot.

Build-blocking (must land in the spines before implement): (1) Persistent seek while pinned + no scrollIntoView progress fight. (2) Pin top / z-index / scroll-margin vs sticky header; 2.4.11 written. (3) Native scroll only (no preventDefault jack); unpin without a modal. (4) One NRV model for both breakpoints; stable panel; arrow vs page-scroll table. (5) Live region: seek vs scrub debounce. (6) Contrast: stone/gold/idle pill text ≥4.5:1; idle glyphs ≥3:1 if they carry state. (7) Dot (and any 6px) hit areas ≥24×24 on the CarouselChrome fallback. (8) Breakpoint / PRM / orientation: chapter id + scrollTop + focus; #crm reset; seek vs wheel cancel. (9) PRM: kill hover/crossfade/climax; matchMedia change; spacer teardown.

Already strong (do not lose): reduced-motion is a real product; no autoplay / no Beat×6 stagger; no long pin on mobile; pills use text navLabels; skip-to-Website is first-class; hash #crm must land Clients at rest; live region string is human (polite + atomic); mocks are decorative; motion is transform/opacity only; copy floor protects cognitive access.

critical

Seek chrome leaves the viewport once the pin starts

EXPERIENCE Component Patterns ChapterPills; DESIGN Layout anatomy; Flow C
Desktop ChapterPills sit above the pin track and are not sticky, so once scrub starts the only skip/seek UI is gone. Keyboard and screen-reader cursor users who entered via scroll must discover Website by scrolling — the opposite of the locked “seek / escape” decision. Tabbing back to a pill scrollIntoViews the intro and fights pin progress.
Fix: Keep seek chrome visible and operable for the entire pin (sticky pills under the header, or a persistent “Website” control). Focusing a pill must not rewrite progress except on explicit Activate; use preventScroll on programmatic focus where needed.
critical

Sticky header + unspecified pin = 2.4.11 Focus Not Obscured

EXPERIENCE Accessibility Floor; State #crm; Responsive Hash; DESIGN pinned anatomy
Sticky marketing header (top-0 z-30) plus an unspecified cinema pin. scroll-mt-24 only fixes hash landing of the section, not position: sticky top on the stage. top: 0 puts ChapterCopy / H3 under the bar; a higher z-index covers header nav (focusable links with no visible target).
Fix: Lock pin top to header height (not 0), pin z-index below the header, scroll-margin on pills ≥ header height, and a written 2.4.11 check: focused pill, focused header link, and chapter H3 are never fully covered while pinned.
critical

Scroll-trap named but not banned; 5.4 extra viewports, no in-track escape

EXPERIENCE Interaction Primitives Pin/Escape/Banned; Accessibility Floor
Also noted by Rubric Flow (low — marathon pin). “Wheel / trackpad / keyboard page scroll all drive the same progress” is how implementers justify preventDefault on wheel/touch/keydown. That is a trap: it breaks assistive cursor scrolling, find-in-page, and Space/PageDown when focus is not on a button. Six × 90vh ≈ 5.4 extra viewports.
Fix: Native scroll only. Map scrollY → chapter index. Forbid preventing default on wheel/touch/keyboard. “Escape” = continue scrolling and a visible seek control. Do not capture Space/PageDown/Home/End except when a seek control is actually focused.
high

PRM fallback is the right idea and the wrong spec completeness

EXPERIENCE State prefers-reduced-motion; Backup & Rollback; DESIGN ChapterPills hover
Also flagged by Rubric State (medium — mid-session PRM). Gaps: (1) DESIGN still specifies idle-pill hover translateY(-2px) and 400ms chapter-crossfade with no PRM exception; live CSS kills enter animation but not pill hover lift. (2) No rule for PRM toggling mid-pin — spacer must collapse without leaving the visitor stranded ~400vh down. (3) Reduced-motion desktop gains dots/chevrons while motion-safe desktop drops them — skip-parity untested.
Fix: PRM = current carousel behavior and chrome, including hover/animation kill. Listen to matchMedia('change'). On PRM flip: remount CarouselChrome, restore chapter id, do not keep pin spacer height.
high

Live region treats scrub like a click — six polite announcements per flick

EXPERIENCE Voice and Tone; LiveRegion; State In-pin chapter n
“Announce chapter changes… Showing {navLabel}: {title}” on every chapter change will fire six polite announcements on a single flick (more if hysteresis flickers). Polite queues drop, interrupt bullet reading, and desync from the visual chapter. Today the region only updates on goTo (explicit); cinema makes chapter a scroll side effect and keeps the same string.
Fix: Announce on explicit seek immediately. For scrub: update visual + aria-current/aria-selected continuously; debounce the live region until progress settles (scrollend or ~200–400ms idle); suppress duplicate strings. Keep polite + atomic. Never assertive on scrub.
high

Name, role, value is a coin toss — tablist vs aria-current

EXPERIENCE Accessibility Floor; Interaction Pills keyboard
Also flagged by Rubric State as medium (uncommitted). “Prefer tablist if it maps 1:1” or scroll-seek buttons with aria-current is not a floor. Tablist without APG plus a single tabpanel whose id changes fails 4.1.2 in spirit. Arrow-keys-on-pill collide with page-scroll.
