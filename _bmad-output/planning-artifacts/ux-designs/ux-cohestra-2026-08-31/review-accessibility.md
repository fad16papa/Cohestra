# Accessibility Review — Landing Product Cinema

Lens: WCAG 2.2 AA on a consumer conversion surface. Critique is of the **spines** (`DESIGN.md`, `EXPERIENCE.md`), not of an implementation. Live `MarketingProductCarousel` is cited only as behavioral ground truth — what cinema inherits, what it must not regress, and where “keep today’s chrome” would ship known failures.

## Overall verdict

The spines want the right floor — reduced-motion is the real carousel, not a dimmed film; pills are named; there is no autoplay; mobile does not pin — then leave the dangerous parts as `[ASSUMPTION]`. Desktop cinema as drawn is a **sticky-on-sticky scroll machine** whose only skip control **leaves the viewport**, whose live region will **narrate the scrub**, and whose inherited stone/gold pairings **fail 1.4.3** on the copy and seek labels the section now depends on. Do not build until pin geometry, seek persistence, announcement policy, and control contrast/size are locked. Polish can wait; **trapping Priya in 540vh of unlabeled progress cannot**.

## Findings

- **critical** Desktop ChapterPills sit *above* the pin track and are not sticky, so once scrub starts the only skip/seek UI is gone. Keyboard, screen-reader cursor users who have already entered the track, and anyone who arrived via scroll rather than hash must **discover Website by scrolling** — the opposite of the locked “seek / escape” decision. Tabbing back to a pill then `scrollIntoView`s the intro, which **fights pin `progress`** (jump to Clients, skip chapters, or yank the stage). (EXPERIENCE Component Patterns ChapterPills + Layout anatomy in DESIGN; Interaction Primitives “Pills”; Flow C.) *Fix:* Keep seek chrome **visible and operable for the entire pin** (sticky pills under the header, or a persistent “Website” control). Spec: focusing a pill **must not** rewrite progress except on explicit Activate; `preventScroll` on programmatic focus where needed.

- **critical** Sticky marketing header (`top-0 z-30`, ~header height) plus an unspecified cinema pin is a WCAG **2.4.11 Focus Not Obscured** and reading-order collision waiting to ship. Floor says the pin must not cover the focused pill or the header, and that `#crm` uses `scroll-mt-24` — that offset **only** fixes hash landing of the *section*, not `position: sticky` `top` on the stage. `top: 0` puts ChapterCopy / H3 under the bar; a higher z-index **covers header nav** (focusable links with no visible target). (EXPERIENCE Accessibility Floor last bullet; State `#crm`; Responsive “Hash `#crm` + sticky marketing header”; DESIGN pinned anatomy.) *Fix:* Lock pin `top` to header height (not `0`), pin `z-index` **below** the header, `scroll-margin` on pills ≥ header height, and a written 2.4.11 check: focused pill, focused header link, and chapter H3 are never fully covered while pinned.

- **critical** Scroll-trap risk is named (“no scroll-jack”) but not contractually banned. “Wheel / trackpad / keyboard page scroll all drive the same progress” is how implementers justify `preventDefault` on `wheel`/`touchmove`/`keydown` — that **is** a trap: it breaks assistive cursor scrolling, browser find-in-page jumps, and Space/PageDown when focus is not on a button. Six × `{spacing.cinema-chapter-scroll}` (90vh) ≈ **5.4 extra viewports** with no in-track escape key. (EXPERIENCE Interaction Primitives Pin/Escape/Banned; Accessibility Floor “pin must not trap focus.”) *Fix:* Native scroll only. Map `scrollY` → chapter index. **Forbid** preventing default on wheel/touch/keyboard. “Escape” = continue scrolling *and* a visible seek control (see finding 1). Do not capture Space/PageDown/Home/End except when a seek control is actually focused.

- **high** `prefers-reduced-motion` fallback is the right *idea* and the wrong *spec completeness*. Flow D / state table correctly swap to CarouselChrome (no pin, no scrub, no climax, instant swap). Gaps: (1) DESIGN still specifies idle-pill hover `translateY(-2px)` and 400ms `{components.chapter-crossfade}` with no PRM exception on those tokens; live CSS already kills `.marketing-product-carousel-enter` but **not** pill hover lift. (2) No rule for **PRM toggling mid-pin** (OS setting change): spacer must collapse without leaving the visitor stranded 400vh down the page. (3) Reduced-motion desktop **gains** dots/chevrons (CarouselChrome) while motion-safe desktop **drops** them — operable, but parity of *how* you skip is not written, so cinema-only bugs will not be tested on the fallback. (EXPERIENCE State `prefers-reduced-motion`; Backup & Rollback; DESIGN ChapterPills hover + chapter-crossfade + ClimaxMicroBeat.) *Fix:* PRM = current carousel **behavior and chrome**, including hover/animation kill. Listen to `matchMedia('change')` (live code already does — preserve). On PRM flip: remount CarouselChrome, restore chapter **id**, **do not** keep pin spacer height.

- **high** Live region policy treats scrub like a click. “Announce chapter changes… `Showing {navLabel}: {title}`” on every chapter change will fire **six polite announcements** on a single flick through the pin (more if hysteresis flickers at boundaries). Polite queues drop, interrupt reading of the bullets, and desync from the visual chapter. Seek-via-pill *should* announce; pixel-scrub should not spam. Ground truth: today the region only updates on `goTo` (explicit). Cinema makes chapter a **scroll side effect** and keeps the same string. (EXPERIENCE Voice and Tone; LiveRegion; State “In-pin, chapter n”; Interaction hysteresis assumption.) *Fix:* Announce on **explicit seek** (pill, tab, chevron, keyboard activate) immediately. For scrub: update visual + `aria-current`/`aria-selected` continuously; **debounce** the live region until progress settles (e.g. scrollend or ~200–400ms idle), and suppress duplicate strings. Keep `polite` + `atomic`. Never `assertive` on scrub.

- **high** Name, role, value is an unresolved fork: “prefer tablist if it maps 1:1” *or* scroll-seek buttons with `aria-current`. That is not an accessibility floor — it is a coin toss. Tablist without APG (roving tabindex, arrows, Home/End, one tab stop) plus a **single tabpanel whose `id` changes** (live carousel: inactive `aria-controls` point at nodes that are not in the DOM) fails 4.1.2 in spirit and confuses AT. Arrow-keys-on-pill (desktop assumption) **collide with page-scroll** while focus is on the seek row — Down/Space must not be eaten if you are not claiming a tablist. (EXPERIENCE Accessibility Floor “Name, role, value”; Interaction Pills keyboard; mobile keeps today’s tablist.) *Fix:* **Lock one model.** Recommended: both breakpoints use **tablist/tab/tabpanel** with roving tabindex, Left/Right (Home/End), `aria-selected`, **one selected tab in tab order**, and a **stable panel id** (or six panels with `hidden`). Do not mix `aria-current` on pills and `aria-selected` on the same node. Chevrons remain buttons, not tabs. Write what Up/Down/Space/PageDown do in one sentence.

- **high** Contrast floor restates failing Midnight Atelier pairings as if they were AA. Measured on the cinema canvas `{colors.paper-warm}` `#F3F5F7`: `{colors.stone}` `#8B939C` leads **2.85:1** (needs **4.5:1** — `{typography.chapter-lead}` is ~16px regular, not large text); `{colors.gold}` `#A68B5B` eyebrows **2.97:1** at **13px** `{typography.section}` (also not large) — “Website builder · Pro” is **plan information**, not decoration; idle pill `{colors.stone}` on `{colors.paper}` is **3.00:1** for `text-sm` labels — the **primary seek names**. DESIGN: “Do not lighten stone for cinema density.” That instruction **cements 1.4.3 failures** on the conversion surface. Ink/paper titles and active pill paper-on-ink **pass**. Lagoon on paper-warm **~5.8:1** passes. (DESIGN Colors contrast paragraph; ChapterPills; ChapterCopy; tokens.) *Fix:* Cinema-specific text tokens, not a rebrand: darken stone for leads/idle labels to ≥4.5:1 on paper-warm (ink-soft `#141C24` works; a darker stone can too). Gold eyebrows: darker gold or ink + a non-color-only “Pro” treatment. Do not ship idle chapter names at 3:1.

- **high** WCAG **2.5.8 Target Size (Minimum)** is already failed by the chrome cinema **preserves as the mobile + PRM path**. `{components.chapter-dot-idle}` is **6×6px** with `gap-1.5` (6px) — neither 24×24 nor 24px spacing between undersized targets. Active dot is 24×**6**. Live buttons: `h-1.5 w-1.5`. Pills at `padding: 8px 16px` are ~36px tall (AA-ok, AAA-short). Chevrons at 40px pass. Desktop cinema **removes** chevrons, so motion-safe `lg+` has no 40px pager at all. (DESIGN chapter-dot-* ; CarouselChrome; EXPERIENCE “dots/chevrons not required” on desktop.) *Fix:* Hit area ≥24×24 (padding / `min-h/min-w` with visible 6px glyph). Keep names (`Go to {navLabel}`). If desktop has no dots, **pills must stay reachable** (finding 1) — do not delete the only oversized control.

- **high** Resize across `lg` and orientation change are an assumption, not a failure mode. “Remount the appropriate model without losing chapter id” ignores: **pin spacer height** (collapsing ~540vh **jumps** the page; injecting it **lands mid-scrub** unless `scrollTop` is rewritten to that chapter’s range); **focus loss** when chevrons unmount at `lg+` or the sticky stage remounts; iPad landscape/split-view **oscillating** across 1024. Mid-scroll **smooth-seek vs wheel** is unspecified — two `scrollTop` owners. Header **Clients** → `/#crm` while already pinned on Website: same-hash click often **does nothing**; state table wants Clients at progress 0. (EXPERIENCE State Resize; Hash; Seek via pill smooth-scroll; Responsive `lg`.) *Fix:* On breakpoint/PRM change: map `id`, **synchronously** set scroll so the section is in view at the matching model (carousel: no spacer; cinema: progress at chapter *i* start), move focus to the active pill if focus was inside unmounted chrome. Hash/nav to `#crm` **always** resets to Clients even when already in section. Seek smooth-scroll **cancels** on user wheel/touch/Escape.

- **medium** Non-text contrast **1.4.11** on idle chrome: `{colors.line}` `#E6E9ED` on paper-warm is **~1.11:1** (idle dots); idle pill border line-on-paper **~1.18:1**; idle pill fill paper on paper-warm is nearly invisible. If the border/dot is how you see “this is a control / this many chapters,” it fails 3:1. Active lagoon dot passes. (DESIGN chapter-pill-idle, chapter-dot-idle.) *Fix:* Idle indicators ≥3:1 against canvas (`line-strong` `#D0D5DB` is still short; use stone/ink at ≥3:1 for glyphs). Idle pill: stronger border or ink-muted text (with 1.4.3 fix above).

- **medium** Focus appearance is hand-waved (“existing marketing focus”). Carousel pills/dots have **no** `focus-visible` ring in ground truth — global `outline-ring/50` plus `ring/50` on paper-warm is a **weak** tell against `{colors.paper-warm}`. Sticky pin makes a clipped or header-overlapped ring a 2.4.7 / 2.4.13-adjacent failure even if you only claim 2.4.7. (EXPERIENCE Accessibility Floor; DESIGN does not spec a cinema focus token.) *Fix:* Explicit `focus-visible` ring: solid ink or lagoon **≥3:1** vs adjacent paper-warm, offset so sticky header cannot clip it (`scroll-margin`).

- **medium** Mobile tablist is “keep today’s” including today’s holes: all six tabs in tab order (no roving tabindex), **no** arrow-key behavior in live code, `<sm` horizontal `overflow-x-auto` nowrap row, one swapping tabpanel. Cinema adds `aria-live` on the same click path — activating a tab then **double-speaks** (tab selected + “Showing…”). Horizontal overflow without a visible “more” affordance hides Follow-up…Website off-screen; keyboard will scroll the row on Tab, touch users may not know it scrolls. (EXPERIENCE Mobile / CarouselChrome; DESIGN Responsive `<sm`; live tablist.) *Fix:* APG tablist on mobile too. `aria-label="Product surfaces"` stays. Delay or skip live region when `aria-selected` already changed from a user activate. Below `sm`, do not rely on overflow alone: wrap (as `sm+` does) **or** show peek/scroll hint; do not require a horizontal gesture (2.5.1) to reach Website.

- **medium** Mocks stay `aria-hidden` (correct — they decorate the copy) but the spine never requires **no tab stops**. `aria-hidden` does not remove descendants from tab order; a future “real product” mock with a button would create **2.4.3 / 4.1.2** hidden focus. Ground truth mocks are currently non-interactive `div`s — cinema must keep that contract. (EXPERIENCE ProductFrame; Accessibility Floor.) *Fix:* `aria-hidden` **and** `inert` (or no controls in mocks). Written test: tab from last pill to next **page** landmark with zero stops inside the frame.

- **medium** ClimaxMicroBeat is motion-safe and optional, but it is still motion tied to **entering** Website — including skip-to-Website (Flow C). Reduced-motion skips it; a vestibular user **without** PRM set still gets scale/lift after a seek they thought was a static jump. 500ms transform on a large frame is more than a 2% footnote. (DESIGN ClimaxMicroBeat; EXPERIENCE Skip to Website + Climax armed.) *Fix:* Fire only on **scrub-entry** from Reports, not on pill skip; or drop the beat (it is already optional). Never combine with copy crossfade in a way that moves the H3.

- **low** “Escape” in the spine means “keep scrolling.” Keyboard users will try **Esc**. It will do nothing. Harmless unless a future scroll-lock appears. (EXPERIENCE Unpin / Escape.) *Fix:* Either wire Esc to unpin (scroll to end of track / next section) or stop calling scroll “escape.”

- **low** Light-only cinema (`DESIGN` theme.modes: light) means `prefers-color-scheme: dark` visitors still get paper-warm. Not a cinema regression vs current marketing, but forced light on a dim room is a contrast/glare issue the floor does not mention. *Fix:* Out of scope for this story; do not invent a dark theater (correctly banned). Revisit at shell level.

- **low** No bypass besides heading navigation to skip the **whole** cinema (2.4.1). Six tab stops is the same as today; the pin adds time, not stops. A “Skip product tour” link would be kindness, not AA-blocking, **if** finding 1 is fixed. *Fix:* Optional skip link to the next section id (pricing / start-free).

## What is already strong

- **Reduced-motion is a real product**, not opacity-cinema: no pin, no scrub, no climax, instant chapter swap; backup file is the fallback. That is the correct 2.3.3-adjacent posture for AA.
- **No autoplay**, no Beat×6 bullet stagger, no video timeline — visitor holds seek; vestibular load is opt-in via scroll, not a timer.
- **No long pin on mobile** — locks out the worst scroll-trap class on phones.
- Pills use **text `navLabel`s**, not icon-only chapter dots-as-primary-nav; skip-to-Website is a first-class legal path (Flow C).
- Hash `#crm` **must land Clients at rest**, not mid-scrub; `scroll-mt-24` intent vs header is the right instinct (incomplete, not absent).
- Live region string is **human** (`Showing {navLabel}: {title}`), `polite` + `atomic`; mocks are **decorative** (`aria-hidden`) so AT is not forced through fake CRM chrome.
- Motion language is **transform/opacity only**; climax is one-shot and skipped under PRM.
- Copy floor (all four bullets, no cinema-caption) protects **cognitive** access — the section remains a readable document, not a film.
- Chevrons already meet target size; rollback path can restore a known keyboard UI.
- Explicit “pin must not trap focus” and “do not hijack exclusively” are the right **intent** — they need to become testable constraints (findings above).

## Build-blocking vs polish

**Must land in the spines before implement**

1. Persistent seek while pinned (pills or equivalent) + no `scrollIntoView` progress fight.
2. Pin `top` / `z-index` / `scroll-margin` vs sticky header; 2.4.11 written.
3. Native scroll only (no `preventDefault` jack); unpin without a modal.
4. One NRV model (tablist APG **or** buttons + `aria-current`) for **both** breakpoints; stable panel; arrow vs page-scroll table.
5. Live region: seek vs scrub debounce.
6. Contrast: stone/gold/idle pill text on paper-warm ≥4.5:1 for actual text; idle glyphs ≥3:1 if they carry state.
7. Dot (and any 6px) hit areas ≥24×24 on the CarouselChrome path cinema calls the a11y fallback.
8. Breakpoint / PRM / orientation: chapter id + scrollTop + focus; `#crm` reset; seek vs wheel cancel.
9. PRM: kill hover/crossfade/climax; `matchMedia` change; spacer teardown.

**Can follow (do not block first build if the above is in the spine)**

- ClimaxMicroBeat skip-vs-scrub nuance; Esc-to-unpin naming; skip-past-section link.
- Dark scheme (shell-level).
- AAA 44px targets on pills; 2.4.13 focus appearance extras beyond a 3:1 ring.
- Softening double-announce on explicit tab activate.
- `inert` on mocks as defense-in-depth (require it in the contract; implementation is small).

**Do not implement cinema while findings marked critical/high above are still `[ASSUMPTION]`.** Rollback to today’s carousel remains the accessible conversion surface; cinema is not an upgrade until skip, pin geometry, announcement, and contrast are specified as tests, not vibes.
