## Overall verdict

The pair is an extractable **behavioral and token contract** for Live Proof Cinema: A1–A7 are locked, contrast tokens are hexed with AA targets, pin math is numeric, and Maya’s four journeys cover the intent’s conversion paths. It is not yet a complete **visual contract** — `mockups/` and `wireframes/` are empty, and the memlog’s anti-pattern screenshot is missing from `imports/` — so a consumer can implement rules without inventing decisions, but must still invent the pinned composition. Downstream architecture / story-dev can source-extract cleanly for copy, seek/pin/PRM, and a11y; they cannot source-extract the stage layout from a picture.

The accessibility lens shifts that from “invent the pinned composition from ASCII” to **do not extract the exploded anatomy**. Contrast tokens, Focus≠seek, scrub-debounced live region, PRM→click-tabs, and hash-resets-to-Clients are real floors — keep them. Do **not** treat the Accessibility Floor as shippable. Two locks fight themselves: (1) pills and stage both `top: 6rem` / `z-20`, which re-creates **2.4.11** occlusion; (2) `tablist/tabpanel` plus `aria-hidden`+`inert` on an undefined “stage,” which can hide FeelingCopy or leave a hidden panel. The live mount then adds a third: real WhatsApp/Publish chrome that must not trap, must not be fake, must inner-scroll, and must not steal the pin’s wheel. Those four cannot be true of one subtree. Conditionally specified, not AA-ready — fix the geometry and the hidden-vs-panel map before extract.

Source counts: Rubric **0 critical / 1 high / 7 medium / 18 low**; Accessibility **2 critical / 6 high / 5 medium / 3 low**. Merged unique below (InkProgress visual-gap + 4.1.2 holes folded into one medium).

### Critical (2)

- **[Accessibility]** Pin + sticky pills vs header still fail 2.4.11 as specified. The floor writes the right *check* (focused pill, header link, feeling H3 never fully covered) and the wrong *geometry*. `{components.seek-pill-sticky}` and the pin both use `top: {spacing.header-offset}` (6rem) and both `z-20`; header is `z-30`. Two stickies at the same `top` occupy the same band: the stage (min-height 520px) paints over the pill row and the left-column H3, or the pill band covers the feeling word. `scroll-mt-24` only offsets hash landing of `#crm`, not stacking of pill height under the bar. Ground truth already does this correctly as **one** sticky (`top-24 z-20 h-[calc(100vh-6rem)]`) with the tablist *inside* that box — the DESIGN anatomy drawing would regress it. (DESIGN pinned anatomy + `seek-pill-sticky` + Layout “Pin `top` = header-offset”; EXPERIENCE SeekPills / Accessibility Floor last bullet; live `marketing-product-cinema.tsx` sticky wrapper.) *Fix:* One sticky cinema chrome under the header. Pills are a `shrink-0` row *inside* it; the FeelingCopy+frame fills the rest. If two stickies are required, stage `top` = header height **+** pill-band height, pills `z` above the stage, both below header `z-30`. Write the 2.4.11 test against that math, not against a shared 6rem.

- **[Accessibility]** `aria-hidden`+`inert` target is “stage,” but the accessible `tabpanel` is unnamed. Model table: “Stage a11y = `aria-hidden` and `inert`.” ProductFrame row repeats “Stage: `aria-hidden` and `inert`.” CinemaStage **is** FeelingCopy + ProductFrame. Hide the pair and AT loses the H3, scene, and outcomes — leaving a tablist whose panel is empty/hidden (**4.1.2** / APG: tabs must control a visible panel) plus a first-person live-region riddle. Hide only the frame (as today’s visual column does) and FeelingCopy can *be* the stable panel — but the spine never says that. `PrimaryButton` “not inside the inert stage” implies the stage is the whole pinned pair. (EXPERIENCE Model “Stage a11y”; ProductFrame; Accessibility Floor; DESIGN CinemaStage / FeelingCopy / ProductFrame; live copy column is **not** `aria-hidden`, visual **is**.) *Fix:* **Frame only:** `aria-hidden` + `inert` on ProductFrame. FeelingCopy **is** the `tabpanel` (`id` stable, `aria-labelledby` active tab). Pills `aria-controls` that id. Written test: headings/scene are in the accessibility tree; zero tab stops inside the frame; Tab from last pill lands on the next page landmark, never a WhatsApp button.

### High (7)

- **[Rubric: Visual reference coverage]** No promoted mock or wireframe of the **desktop pin cinema** (stable stage + sticky SeekPills + 32/68 split) — the novel interaction. Only ASCII anatomy plus tokens. `mockups/` and `wireframes/` absent. (DESIGN.md §Layout & Spacing; EXPERIENCE.md §CinemaStage / Flow A.) *Fix:* At least one `mockups/` HTML (Clients pinned + Follow-up climax) linked at CinemaStage / Flow A; name what it illustrates; keep spines-win.

- **[Accessibility]** Live product UI is specified as real will and as a poster. DESIGN: lagoon is “true product actions inside the live stage (WhatsApp, Publish).” EXPERIENCE: clicks blocked, inert, pills are the only control. Sighted users get login-true buttons that do nothing (**1.3.1** / consistent identification). That is not “no fake interactivity”; it is fake interactivity with better pixels than the old mocks. Keyboard is saved only if inert holds; pointer users learn the product is a lie. (DESIGN Colors / Craft 5; EXPERIENCE ProductFrame + Stage a11y; intent “Stage inert… clicks blocked.”) *Fix:* Treat the frame as **preview**, not an operable desk. No hover/cursor/active styles leaking from admin buttons. Optional visible caption: this is a walkthrough, not a session. Do not advertise in-frame Publish/WhatsApp as will — will is the post-cinema CTA. If a control cannot activate, it must not look enabled.

- **[Accessibility]** “Inner scroll for depth” fights native pin scrub. Pin maps page `scrollY` → surface index and **forbids** `preventDefault` on wheel. The frame is a cinematic mask (`overflow: hidden`) that is also “internally scrollable.” Wheel over Clients will scroll the list, not the house — cinema feels stuck; hysteresis never fires. `pointer-events: none` (today’s visual) blocks inner scroll **and** clicks, which satisfies inert but contradicts “scroll for depth.” Nested scrollports are a pointer trap even when keyboard is free (**2.1.2**-adjacent for anyone using a cursor as their AT). (EXPERIENCE Interaction Primitives; ProductFrame; DESIGN `cinematic-mask`.) *Fix:* Pick one. Recommended: **no inner scroll**. Crop with the mask; page scroll owns the wheel. If depth-scroll is mandatory, it exists only when the pointer is inside a clearly labeled overflow region **and** does not start until the inner pane has overflow — never on the frame chrome — and pin progress ignores wheel over that pane. Document the hit-test. Do not ship both “native scroll only” and “inner scroll allowed” as equal rules.

- **[Accessibility]** Visible live UI still fails 1.4.3 even when cinema copy passes. `{colors.stone-cinema}` / `{colors.gold-cinema}` on `{colors.paper-warm}` measure **5.58:1** and **6.06:1** — the *copy* floor is honest. The trust hire is the mounted admin/preview, which still uses inherited `{colors.stone}` **2.85:1** on paper-warm (and whatever muted chips the bodies ship). **1.4.3 applies to visible text**, including `aria-hidden` subtrees. A conversion section that is AA in the left column and 2.85:1 in the hero object is not AA. (DESIGN Colors “LOCKED ≥4.5:1”; EXPERIENCE Accessibility Floor first bullet; Data & Mount presentational bodies.) *Fix:* Cinema mount uses the same contrast tokens as marketing (stone-cinema / ink for secondary text), or a dedicated DemoClub presentational theme. Do not iframe a production admin stylesheet unmodified. QA contrast on Elena’s meta line, not only the feeling scene.

- **[Accessibility]** APG tablist is locked; selected vs focused is not. “Focus moves **highlight** only; Activate seeks” plus “selected = ink fill” plus `aria-selected` on in-pin room *n* describes three properties and one word (“highlight”). Implementers will ink-fill on focus (seek on arrow — banned) or set `aria-selected` on focus (AT thinks the room changed — **4.1.2**). Manual-activation APG requires: ink + `aria-selected` follow the **seeked** room; focus-visible ring is the only focus tell; two pills may be emphasized at once. Floor also says “one selected tab in tab order,” which conflicts with independent `focusIndex` after scrub: Tab back into the list lands on a stale Clients tab while Website is selected. (EXPERIENCE SeekPills; Interaction Pills; State In-pin / Focus; Accessibility Floor NRV; live code already splits `isSelected` vs `isFocused` but does not resync roving to selected on blur.) *Fix:* Write the dual-state. `aria-selected` ⇔ progress room ⇔ ink. Focus ⇔ ring only. Left/Right/Home/End move focus with `preventScroll`; Enter/Space Activate. On Tab-in (or blur of the tablist), roving `tabIndex={0}` returns to the **selected** tab. Do not `preventDefault` Up/Down/PageDown; Space only when a tab is focused.

- **[Accessibility]** Hash `#crm` restore is a state, not a mechanism. State table: hash always scrolls the section into view, Clients at progress 0 / index 0, including when already in-section. Header **Clients** is `href="/#crm"`. Same-document clicks on an already-current hash **do not fire `hashchange`** — today’s handler never runs; the visitor stays on Website. Spec also does not say whether restore **moves focus**. Live cinema currently `focusTab(clients)` on hash, yanking focus from the header link (**2.4.3**). (EXPERIENCE State Hash / Hash while already in section; Header nav contract; Interaction Hash; live `onHash` + `focusTab`.) *Fix:* Intercept header/in-page `#crm` activation (click + Next.js same-hash), always `resetToClients` + scroll with `scroll-mt-24`. **Do not** move focus unless focus was inside cinema chrome that unmounted. After restore, do not re-announce unless the room actually changed.

- **[Accessibility]** Mobile parity is story-parity, not access-parity. `< lg` is click-tabs (good — no pin trap) with “same live bodies, **scaled**” inside a crop mask. Scaling admin density below 16px, or clipping the operable region of a table, fails low-vision reading even if 1.4.4 browser zoom still works (inner `transform: scale` **fights** zoom). Horizontal-scroll tablist “below `sm` as needed” still hides Website off-screen without a peek — **2.5.1** path-gesture to reach a room. Dots at 24×24 are specified; pills at `8px 16px` + 12px label are ~32px tall (2.5.8 pass, 2.5.5 fail — AA-ok). (DESIGN form factor / CarouselChrome / seek-dot; EXPERIENCE Responsive `<sm` / Mobile; Flow B.) *Fix:* No CSS-scale of live roots. Reflow/crop, don’t shrink type. Below `sm`, **wrap** pills (same as `sm:flex-wrap`) or show a peek + chevrons; do not require a horizontal swipe to reach Website. Keep 24×24 dots; keep chevron 40px on this path.
