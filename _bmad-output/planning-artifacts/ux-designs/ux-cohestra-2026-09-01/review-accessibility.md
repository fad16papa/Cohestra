# Accessibility Review — Live Proof Cinema

Lens: WCAG 2.2 AA on a consumer-conversion marketing surface. Critique is of this delta’s spines (`DESIGN.md`, `EXPERIENCE.md`), not of a finished implementation. Live `web/components/marketing/marketing-product-cinema.tsx` is cited only as ground truth — what the prior cinema already got right, and what this anatomy would regress.

Prior cinema (`ux-cohestra-2026-08-31`) blocked on sticky-seek absence, unspecified pin vs header, live-region spam, NRV coin-toss, and stone/gold **1.4.3** failures. Those *intents* are now named. This review does not re-litigate closed locks. It attacks whether the locks **compose**, and whether **live product-as-proof** reopened worse holes than decorative mocks.

## Overall verdict

**Conditionally specified, not AA-ready.** Contrast tokens, Focus≠seek, scrub-debounced live region, PRM→click-tabs, and hash-resets-to-Clients are real floors — keep them. Do **not** treat the Accessibility Floor as shippable. Two locks fight themselves: (1) pills and stage both `top: 6rem` / `z-20`, which re-creates **2.4.11** occlusion the last review made blocking; (2) `tablist/tabpanel` plus `aria-hidden`+`inert` on an undefined “stage,” which can hide FeelingCopy or leave a hidden panel. The live mount then adds a third: real WhatsApp/Publish chrome that must not trap, must not be fake, must inner-scroll, and must not steal the pin’s wheel. Those four cannot be true of one subtree. Fix the geometry and the hidden-vs-panel map before extract; otherwise implementers will copy `top-24` onto two stickies and `inert` onto the tabpanel.

## Findings

### Critical

- **critical — Pin + sticky pills vs header still fail 2.4.11 as specified.** The floor writes the right *check* (focused pill, header link, feeling H3 never fully covered) and the wrong *geometry*. `{components.seek-pill-sticky}` and the pin both use `top: {spacing.header-offset}` (6rem) and both `z-20`; header is `z-30`. Two stickies at the same `top` occupy the same band: the stage (min-height 520px) paints over the pill row and the left-column H3, or the pill band covers the feeling word. `scroll-mt-24` only offsets hash landing of `#crm`, not stacking of pill height under the bar. Ground truth already does this correctly as **one** sticky (`top-24 z-20 h-[calc(100vh-6rem)]`) with the tablist *inside* that box — the DESIGN anatomy drawing would regress it. (DESIGN pinned anatomy + `seek-pill-sticky` + Layout “Pin `top` = header-offset”; EXPERIENCE SeekPills / Accessibility Floor last bullet; live `marketing-product-cinema.tsx` sticky wrapper.) *Fix:* One sticky cinema chrome under the header. Pills are a `shrink-0` row *inside* it; the FeelingCopy+frame fills the rest. If two stickies are required, stage `top` = header height **+** pill-band height, pills `z` above the stage, both below header `z-30`. Write the 2.4.11 test against that math, not against a shared 6rem.

- **critical — `aria-hidden`+`inert` target is “stage,” but the accessible `tabpanel` is unnamed.** Model table: “Stage a11y = `aria-hidden` and `inert`.” ProductFrame row repeats “Stage: `aria-hidden` and `inert`.” CinemaStage **is** FeelingCopy + ProductFrame. Hide the pair and AT loses the H3, scene, and outcomes — leaving a tablist whose panel is empty/hidden (**4.1.2** / APG: tabs must control a visible panel) plus a first-person live-region riddle. Hide only the frame (as today’s visual column does) and FeelingCopy can *be* the stable panel — but the spine never says that. `PrimaryButton` “not inside the inert stage” implies the stage is the whole pinned pair. (EXPERIENCE Model “Stage a11y”; ProductFrame; Accessibility Floor; DESIGN CinemaStage / FeelingCopy / ProductFrame; live copy column is **not** `aria-hidden`, visual **is**.) *Fix:* **Frame only:** `aria-hidden` + `inert` on ProductFrame. FeelingCopy **is** the `tabpanel` (`id` stable, `aria-labelledby` active tab). Pills `aria-controls` that id. Written test: headings/scene are in the accessibility tree; zero tab stops inside the frame; Tab from last pill lands on the next page landmark, never a WhatsApp button.

### High

- **high — Live product UI is specified as real will and as a poster.** DESIGN: lagoon is “true product actions inside the live stage (WhatsApp, Publish).” EXPERIENCE: clicks blocked, inert, pills are the only control. Sighted users get login-true buttons that do nothing (**1.3.1** / consistent identification). That is not “no fake interactivity”; it is fake interactivity with better pixels than the old mocks. Keyboard is saved only if inert holds; pointer users learn the product is a lie. (DESIGN Colors / Craft 5; EXPERIENCE ProductFrame + Stage a11y; intent “Stage inert… clicks blocked.”) *Fix:* Treat the frame as **preview**, not an operable desk. No hover/cursor/active styles leaking from admin buttons. Optional visible caption: this is a walkthrough, not a session. Do not advertise in-frame Publish/WhatsApp as will — will is the post-cinema CTA. If a control cannot activate, it must not look enabled.

- **high — “Inner scroll for depth” fights native pin scrub.** Pin maps page `scrollY` → surface index and **forbids** `preventDefault` on wheel. The frame is a cinematic mask (`overflow: hidden`) that is also “internally scrollable.” Wheel over Clients will scroll the list, not the house — cinema feels stuck; hysteresis never fires. `pointer-events: none` (today’s visual) blocks inner scroll **and** clicks, which satisfies inert but contradicts “scroll for depth.” Nested scrollports are a pointer trap even when keyboard is free (**2.1.2**-adjacent for anyone using a cursor as their AT). (EXPERIENCE Interaction Primitives; ProductFrame; DESIGN `cinematic-mask`.) *Fix:* Pick one. Recommended: **no inner scroll**. Crop with the mask; page scroll owns the wheel. If depth-scroll is mandatory, it exists only when the pointer is inside a clearly labeled overflow region **and** does not start until the inner pane has overflow — never on the frame chrome — and pin progress ignores wheel over that pane. Document the hit-test. Do not ship both “native scroll only” and “inner scroll allowed” as equal rules.

- **high — Visible live UI still fails 1.4.3 even when cinema copy passes.** `{colors.stone-cinema}` / `{colors.gold-cinema}` on `{colors.paper-warm}` measure **5.58:1** and **6.06:1** — the *copy* floor is honest. The trust hire is the mounted admin/preview, which still uses inherited `{colors.stone}` **2.85:1** on paper-warm (and whatever muted chips the bodies ship). **1.4.3 applies to visible text**, including `aria-hidden` subtrees. A conversion section that is AA in the left column and 2.85:1 in the hero object is not AA. (DESIGN Colors “LOCKED ≥4.5:1”; EXPERIENCE Accessibility Floor first bullet; Data & Mount presentational bodies.) *Fix:* Cinema mount uses the same contrast tokens as marketing (stone-cinema / ink for secondary text), or a dedicated DemoClub presentational theme. Do not iframe a production admin stylesheet unmodified. QA contrast on Elena’s meta line, not only the feeling scene.

- **high — APG tablist is locked; selected vs focused is not.** “Focus moves **highlight** only; Activate seeks” plus “selected = ink fill” plus `aria-selected` on in-pin room *n* describes three properties and one word (“highlight”). Implementers will ink-fill on focus (seek on arrow — banned) or set `aria-selected` on focus (AT thinks the room changed — **4.1.2**). Manual-activation APG requires: ink + `aria-selected` follow the **seeked** room; focus-visible ring is the only focus tell; two pills may be emphasized at once. Floor also says “one selected tab in tab order,” which conflicts with independent `focusIndex` after scrub: Tab back into the list lands on a stale Clients tab while Website is selected. (EXPERIENCE SeekPills; Interaction Pills; State In-pin / Focus; Accessibility Floor NRV; live code already splits `isSelected` vs `isFocused` but does not resync roving to selected on blur.) *Fix:* Write the dual-state. `aria-selected` ⇔ progress room ⇔ ink. Focus ⇔ ring only. Left/Right/Home/End move focus with `preventScroll`; Enter/Space Activate. On Tab-in (or blur of the tablist), roving `tabIndex={0}` returns to the **selected** tab. Do not `preventDefault` Up/Down/PageDown; Space only when a tab is focused.

- **high — Hash `#crm` restore is a state, not a mechanism.** State table: hash always scrolls the section into view, Clients at progress 0 / index 0, including when already in-section. Header **Clients** is `href="/#crm"`. Same-document clicks on an already-current hash **do not fire `hashchange`** — today’s handler never runs; the visitor stays on Website. Spec also does not say whether restore **moves focus**. Live cinema currently `focusTab(clients)` on hash, yanking focus from the header link (**2.4.3**). (EXPERIENCE State Hash / Hash while already in section; Header nav contract; Interaction Hash; live `onHash` + `focusTab`.) *Fix:* Intercept header/in-page `#crm` activation (click + Next.js same-hash), always `resetToClients` + scroll with `scroll-mt-24`. **Do not** move focus unless focus was inside cinema chrome that unmounted. After restore, do not re-announce unless the room actually changed.

- **high — Mobile parity is story-parity, not access-parity.** `< lg` is click-tabs (good — no pin trap) with “same live bodies, **scaled**” inside a crop mask. Scaling admin density below 16px, or clipping the operable region of a table, fails low-vision reading even if 1.4.4 browser zoom still works (inner `transform: scale` **fights** zoom). Horizontal-scroll tablist “below `sm` as needed” still hides Website off-screen without a peek — **2.5.1** path-gesture to reach a room. Dots at 24×24 are specified; pills at `8px 16px` + 12px label are ~32px tall (2.5.8 pass, 2.5.5 fail — AA-ok). (DESIGN form factor / CarouselChrome / seek-dot; EXPERIENCE Responsive `<sm` / Mobile; Flow B.) *Fix:* No CSS-scale of live roots. Reflow/crop, don’t shrink type. Below `sm`, **wrap** pills (same as `sm:flex-wrap`) or show a peek + chevrons; do not require a horizontal swipe to reach Website. Keep 24×24 dots; keep chevron 40px on this path.

### Medium

- **medium — Live region policy is right; the string is not an orientation.** Polite, atomic, explicit-seek immediate, scrub ~300ms/`scrollend`, no assertive, suppress duplicates — keep all of it. Replacing “Showing {navLabel}: {title}” with the first-person **job sentence** (“I won’t lose a person after they scan the QR”) means a scrub-settle announcement has **no room name**. Explicit seek already speaks the tab (“Follow-up, selected”) then the job — complementary, but noisy. Scrub-only users never hear the tab name from the region. (EXPERIENCE Voice live-region pattern; LiveRegion; Accessibility Floor.) *Fix:* `{navLabel}. {job sentence}.` Suppress the region on explicit Activate if the tab’s accessible name already includes `navLabel` **and** the job is in the panel H3 — or delay ~150ms so the tab utterance wins. Never “Chapter N.”

- **medium — PRM→click-tabs is locked in EXPERIENCE and still contradicted by DESIGN motion tokens.** State: `matchMedia` change tears the spacer, remounts CarouselChrome, restores surface **id**, syncs scroll. Climax/hover-lift/crossfade skip under PRM. DESIGN SeekPills still specify idle hover `translateY(-2px)` and `{components.feeling-crossfade}` 400ms with no token-level PRM exception — the last review’s leftover. Motion-safe `lg+` drops dots/chevrons; PRM **gains** them — skip-parity must be tested on both chromes. (DESIGN SeekPills hover / feeling-crossfade / ClimaxMicroBeat; EXPERIENCE PRM state; Backup.) *Fix:* DESIGN: hover-lift and crossfade are motion-safe only. PRM = CarouselChrome behavior **and** chrome. Preserve the remount rule.

- **medium — InkProgress and unnamed tablist/chevrons are leftover 4.1.2 holes.** A7 ships a 2px ink bar under pills. Unspecified role: a `<progress>` will announce on scrub; an unlabeled slider will be operable by accident. Idle track `{colors.line}` on paper-warm is **1.11:1** — acceptable only if the bar is purely decorative (selected **pill** is the teacher) and `aria-hidden`. Tablist has no required accessible name in this spine (live code: `aria-label="Product surfaces"`). Chevrons/dots “call the same Activate” but have no `Go to {navLabel}` / `Previous` names. (DESIGN ink-progress / CarouselChrome; EXPERIENCE InkProgress / Accessibility Floor.) *Fix:* Ink bar: `aria-hidden` presentational div, not `progressbar`. Tablist: `aria-label="Product surfaces"`. Chevrons: buttons with names; dots: `Go to {navLabel}`.

- **medium — iframe `/demo/*` fallback can undo inert.** Fallback is still a full document. `inert` on the host does not reliably kill iframe tab stops in every engine; a focusable demo **is** a **2.1.2** trap (Tab in, no Tab out). Mount failure that “keeps prior inhabited room and announce nothing” while the Website pill remains is a selected-tab/panel lie (**4.1.2**). A5 omit-the-room is the honest path; silent iframe failure is not. (EXPERIENCE Data & Mount Fallback; State Mount failure; A5.) *Fix:* Prefer omit-pill. If iframe ships: `tabindex="-1"`, `inert` on host, `pointer-events: none`, `title` decorative, sandbox without `allow-scripts` if possible. On failure: hide that tab, retarget `aria-controls`, do not leave a selected Website tab on a Clients panel.

- **medium — Feeling copy contrast passes; whisper type can still fail in production.** Gold-cinema **6.06:1** and stone-cinema **5.58:1** on paper-warm at 13px / 16px meet **1.4.3**. The feeling word is `{typography.section}` — 13px uppercase, `letter-spacing: 0.12em`. That pairing is legally AA and optically faint; any `opacity`, `/60`, or `{colors.gold}` fallback (2.97:1) kills it. **1.4.12** user letter-spacing on an already-tracked 13px line will wrap into the sticky pill band if overflow is hidden. (DESIGN feeling-copy / typography.section; Colors “do not use stone/gold.”) *Fix:* No opacity on feeling/scene. Clip test with 1.4.12 spacing. Do not put FeelingCopy under `overflow: hidden` shared with the mask.

### Low

- **low — “Escape” still means “keep scrolling.”** Keyboard users will press Esc. It does nothing. Harmless unless a future `preventDefault` lands. (EXPERIENCE Unpin / Escape.) *Fix:* Stop calling scroll “escape,” or map Esc to scroll to the end of the track / next section.

- **low — Light-only cinema (`theme.modes: [light]`).** `prefers-color-scheme: dark` still gets paper-warm. Correctly not a dark theater; still glare. Out of scope. *Fix:* Shell-level later. Do not invent a cinema dark mode.

- **low — No skip-past-cinema control (2.4.1 kindness).** Roving tablist is one stop; the pin adds time, not stops. A skip link to the post-cinema CTA is optional **if** critical geometry holds. *Fix:* Optional `Skip product walkthrough` to `#` of the CTA band.

## What is already strong

- **Cinema contrast tokens are real, not slogans.** stone-cinema `#5A636E` and gold-cinema `#6E5A32` on paper-warm `#F3F5F7` are **5.58:1** and **6.06:1**. Ink titles and paper-on-ink active pills pass. Inherited stone/gold are explicitly banned for cinema body/seek text. Idle dots specified at stone-cinema ≥3:1 non-text. **Do not lose this.**
- **Focus ≠ seek; Activate seeks; `preventScroll` on programmatic focus** — the correct manual-activation model for a scroll-driven house. Native scroll only; no document `preventDefault` on wheel/touch/PageDown. Space/Enter Activate only when a seek control is focused.
- **Live region cadence** — polite + atomic, debounce scrub, immediate explicit seek, never assertive, never chapter index. (String quality is the remaining issue, not the policy.)
- **PRM is a product, not a dimmer** — click-tabs at every viewport; pin/scrub/climax/crossfade/hover-lift die; spacer teardown on `matchMedia` change with surface **id** restore.
- **No autoplay; climax not on skip; Website is epilogue.** Vestibular beat is one-shot and PRM-skipped.
- **No long pin on mobile.** Same six rooms via tabs; vertical scroll is not trapped. Dots hit ≥24×24; chevrons 40px on that path.
- **Hash means Clients at rest**, not a mid-scrub room, and not `#crm-website`. Intent is right; wire it (finding above).
- Ground-truth cinema already: one sticky under `top-24`, `focus-visible` ink ring with paper-warm offset, `aria-hidden`+`inert`+`pointer-events-none` on the **visual only**, copy as the accessible column, `aria-label="Product surfaces"`, `preventScroll` focus. **Prefer that topology over the new exploded anatomy.**

## Residual risks for implementers

- **Compose stickies before writing CSS.** If you implement DESIGN’s two-band drawing literally, you will fail 2.4.11 in QA. Copy the live sticky wrapper, swap chapter chrome for feeling copy, do not invent a second `top-24`.
- **`inert` is not a polyfill.** iframe `/demo/*`, Safari older than inert, and portaled admin dialogs will leak tab stops. Test Tab from last pill to the post-cinema CTA with every mount strategy (extracted body, iframe, omitted Website).
- **Do not `pointer-events: none` and inner-scroll.** Choose crop-only. If you leave overflow-auto on Clients, pin scrub dies under the cursor.
- **Roving tabindex vs scrub.** Update `aria-selected` on progress; do not move focus on scrub; on Tab-in, land on the selected pill. Mirror today’s `focusIndex`/`activeIndex` split, then resync on tablist blur.
- **Header `text-stone` on paper (~2.85:1)** is outside this file and still the control that fires `#crm`. Not this story’s to restyle unless you touch the shell; do not make cinema the only AA island.
- **Website omit (A5)** must rebuild the tablist (5 tabs, no hole, no `aria-controls` to a missing panel).
- **Resize/`lg` oscillation:** preserve surface **id**, rewrite `scrollTop` for the active model, cancel smooth-seek on wheel. Do not steal focus from the header.
- **QA list (minimum):** 2.4.11 screenshots (focused pill, focused header Clients, feeling H3) while pinned; keyboard Flow C; PRM mid-pin tear; hash click while already on `#crm`; VoiceOver job-sentence after flick-through; contrast eyedropper on scene, idle pill, feeling word, **and** Elena meta in the frame; mobile wrap of six pills at 320px; no inner tab stop.
