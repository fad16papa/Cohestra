## Epic summary

Epic 15 turned Cohestra from a multi-tenant backend into a **tenant-facing public door**: subdomain routing, plan-tier public home surfaces, Host-scoped registration, plan-gated reports and campaigns, and suspended/archived public states. It sits on the Epic 11–14 spine (tenant entity, JWT, isolation, billing) and directly enabled Epic 16 (share kit, OG metadata, tenant URLs).

## What went well

- **Vertical reuse of enterprise spine** — Epic 15 composed Epic 11–14 primitives (tenant resolution, access evaluator, billing plans) instead of re-implementing isolation or auth.
- **Public door as single entry point** — `TenantHostResolver.ResolveDoorAsync` + `PublicDoorController` unified subdomain routing, plan-tier home selection, and lifecycle states.
- **Plan gates enforced server-side** — Reports and campaigns blocked at API layer (`ValidateReportPlanAsync`, campaign plan gate), not UI-only.
- **Host forwarding pattern** — Middleware + `server-api-fetch.ts` kept tenant context consistent across SSR, login, registration, and public pages.
- **README operator docs** — Subdomain troubleshooting and local `{slug}.localhost` setup documented for Docker UAT.

## What we learned

- **Plan gates break integration test assumptions** — Default tenant migrated to Basic; tests that assumed Pro capabilities (custom report ranges, builder) failed until `EnsureDefaultTenantProPlanAsync` was added (PR #18).
- **Thin story docs hide review debt** — 15.x story files (~30 lines each) lack the adversarial review tables Epics 13–14 and 16 captured; lessons surfaced only in git history and downstream epics.
- **Server/client API split is a recurring boundary** — 15.4 split registration fetch modules; Epic 16 hit the same pattern with `public-door-api.ts` / `next/headers`.
- **Epic spec AC ≠ story AC gaps** — SendGrid sender verification, explicit access-matrix registration messaging, and nip.io apex tightening were in epic spec or deferred-work but not closed in 15.x artifacts.
- **SM-1 gate did not extend to new surfaces** — Epic 13.4 isolation gate existed before Epic 15, but public door and plan-gated endpoints were not added to the matrix.

## Challenges and growth areas

- **Bulk single-day delivery** — All 7 stories marked done 2026-07-22 in one commit wave; fast shipping but thin per-story review artifacts.
- **CI integration test fragility** — Plan gates exposed fixture drift; Epic 16 merges still hit failures until PR #18.
- **Isolation coverage gap** — New public door endpoints not explicitly in SM-1 matrix.
- **Epic spec vs delivered scope** — Sender verification, registration access-matrix copy, sender settings UI remain open or undocumented.

## Key insights

1. **Epic 15 is the customer-visible layer** — Everything before it was platform spine; Epic 15 is what operators and visitors actually experience on `{slug}.localhost`.
2. **Plan gates need test bootstrap conventions** — Any new gate must update integration factory defaults or document explicit Pro seeding.
3. **Story doc quality correlates with review catch rate** — Epic 16's adversarial review caught 4 real issues; Epic 15's thin docs mean similar issues may have shipped silently.
4. **Epic 16 depended on Epic 15 door infrastructure** — Tenant URL resolution, Host-scoped public surfaces, and publish dialog URLs all trace to 15.1/15.4.
