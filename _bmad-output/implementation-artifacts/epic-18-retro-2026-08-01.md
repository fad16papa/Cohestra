## What went well

- **Closed the 17.4 CR loop** — All three deferred decisions (CSP, header ownership, Redis fail policy) plus resend OTP from 17.2 CR shipped in one focused epic.
- **Header ownership pattern scaled cleanly** — Story 18.3 established nginx-canonical + `proxy_hide_header`; 18.2 CSP reused the same model without duplicate headers.
- **Shared Redis fault helper** — `RedisRateLimiterOperations` unified six limiters; extending to `RedisOtpStore` fixed Francis's raw StackExchange.Redis leak during resend testing.
- **Report-only CSP first** — Avoided breaking Next.js/builder while still collecting violation signal in DevTools.
- **Operator-driven UAT caught real gaps** — Stopping Redis and hitting resend exposed OTP store path missed by limiter-only 18.4 scope; login verify UX gap found when OTP screen was closed.

## What we learned

- **Two OTP limits confuse operators** — Resend limiter (5/15 min) vs `AuthOtp:MaxSendAttemptsPerWindow` (3/15 min INCR) can block resend before resend limiter; document wait times and consider aligning caps.
- **ASP.NET ProblemDetails puts extensions at JSON root** — Frontend must read `errorCode` / `verifyTenantSlug` at root, not only under `extensions`.
- **Self-serve vs bootstrap verify are different routes** — `/signup/verify?slug=` vs `/register/verify`; login must branch on `verifyTenantSlug` from API.
- **Never expose exception.Message to clients** — Even Development leaked Redis diagnostics; friendly 503 + client-side sanitize is required.
- **Stacked PRs need retarget after merge** — #35/#36 stayed open after #34/#37 merged overlapping commits; close superseded PRs to avoid confusion.
- **nginx recreate required after header/CSP changes** — `docker compose up -d --force-recreate nginx web` for curl verify.

## Key insights

1. **P2 hardening is code-complete on `main`** — Abuse surfaces (verify, resend, signup IP) have consistent Redis semantics and predictable outage behavior.
2. **Header changes are a two-file rule** — `app.conf` + `app-ssl.conf.template` + canonical TS module + `proxy_hide_header`.
3. **UX belongs in the same epic as security** — Unverified login dead-end would have blocked real operators during launch UAT.
4. **Fail-closed during Redis outage trades availability for abuse safety** — Documented and acceptable for launch; ops rely on `/ready` Unhealthy.
