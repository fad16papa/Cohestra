## Epic summary

Epic 17 closed the P1 security and abuse gaps called out in Epic 12–14 retrospectives and `docs/deploy/enterprise-launch-checklist.md`. Original scope was three stories (handoff, signup OTP throttling, member authz matrix). Story **17.4** was added after a full-app security review to cover operator auth OTP throttling, refresh-token revocation on credential change, production secret validation, HtmlSanitizer patch, and deployment security headers.

## What went well

- **Sequential hardening paid off** — Handoff (17.1) unblocked safe paid signup before abuse tests (17.2) and authz evidence (17.3).
- **Redis sliding-window pattern reused** — Signup verify limiter (17.2) made operator auth limiter (17.4) fast to implement with separate key namespaces.
- **Integration tests with dedicated factories** — `PublicSignupAbuseWebApplicationFactory` and `AuthOtpAbuseWebApplicationFactory` keep low limits isolated from default integration config.
- **Code review caught real prod gaps** — HTTPS nginx template (`app-ssl.conf.template`) was missing headers that `app.conf` had; refresh-token index TTL bug would have weakened revoke-all.
- **Fail-fast production validation** — `ProductionSecurityValidator` blocks placeholder JWT, operator seed, and dev DB creds at startup.

## What we learned

- **Update all nginx templates, not just HTTP pre-TLS config** — Production TLS uses `app-ssl.conf.template`; changing `app.conf` alone does not protect HTTPS traffic.
- **Refresh token user-index TTL must only extend** — `KeyExpireAsync` with `ExpireWhen.GreaterThanCurrentExpiry` prevents shorter-lived tokens from orphaning older sessions from `RevokeAllForUserAsync`.
- **Clear OTP rate-limit counters on success-adjacent paths** — Already-confirmed verify and post-OTP-consume reset must clear failures, not only full password-reset success.
- **Integration test filters need `FullyQualifiedName~`** — Plain `--filter AuthOtpAbuseIntegrationTests` matches zero tests in VSTest.
- **Bootstrap-closed DB blocks HTTP verify-email abuse tests** — Operator seed on shared test DB forces service-layer coverage for operator verify path; reset-password integration test remains the live-stack proof.
- **Story 17.4 was scope expansion done right** — Security review findings became a fourth story with explicit AC instead of silent scope creep in 17.2.

## Key insights

1. **P1 dev hardening for launch is code-complete on `main`** — Ops/product gates (reCAPTCHA keys, droplet deploy, nip.io decision) remain before public production.
2. **Separate Redis key namespaces per abuse surface** — `signup:verify:fail:*` vs `auth:otp:verify:fail:*` prevents cross-flow pollution.
3. **Revoke-all refresh tokens on credential change is non-negotiable** — Must ship with any OTP/password flow hardening.
4. **Enterprise launch checklist should track nginx template parity** — Any header or route change must touch both `app.conf` and `app-ssl.conf.template`.
