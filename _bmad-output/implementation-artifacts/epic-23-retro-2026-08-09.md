- **PRD → UX spec → incremental stories** — Epic drafted in PRD/addendum, UX mocks (#100), then 23.1 list before 23.2–23.4 profile/bulk/follow-up batch.
- **23.1 shippable alone** — Operators got queue value (chips, last outreach, Mark contacted, Open messenger) before profile rework landed.
- **Code review discipline** — Two review patch PRs (#104, #107) before polish merges; caught real CRM issues early.
- **EXPERIENCE.md Clients module** — Lead queue behavioral contract documented; Epic 24 Activities module later mirrored this pattern.
- **Cross-module handoffs** — Activity card **Clients (N)** → `/clients?activityId=…` (Epic 24.3) closes activities ↔ queue loop.
- **Epic 21 synergy** — Viber/WhatsApp branded row actions and `ClientOutreachCoverage` integrate cleanly with queue filters and last-outreach column.

## What we learned

- **Sprint-status drift** — Epic 23 merged Aug 8 but absent from tracker until sprint-planning Aug 9 (#135). Same pattern as Epic 24 early stories.
- **No story files in implementation-artifacts** — Work shipped from UX spec + epics doc directly; harder for agents to resume context without retro/sprint sync.
- **UX validation finds medium gaps post-ship** — Mobile filter collapse, Pro-only checkbox column vs spine, empty-state copy drift — none blocking, all documentable.
- **Registration answers layout** — Long email + consent grid collision required profile patch; now fixed with full-width + `break-all`.
- **Bulk select: spine vs implementation** — Checkboxes visible all plans; campaign handoff Pro-gated. Decide explicitly: hide column or ratify spine.
- **5k performance (SM-7)** — AC exists; operator load-test UAT on load-pro-alpha still recommended.

- **Large 23.2–23.4 batch in one PR (#103)** — Harder to review atomically; 23.1 separation was the right pattern.
- **Story files never created** — No `23-x-*.md` in implementation-artifacts for dev-story/review workflow.

- **23.5 parked** — Merge-suspect chip may suffice; promote only if UAT demands manual merge UI.

## Key insights

1. **Lead queue is a presentation layer on Platform 0** — FR-5–7 baseline + Epic 5 outreach + Epic 7 dashboard; Epic 23 adds operator-scale UX, not new domain entities.
2. **Column collision invariants matter at 5k rows** — `min-w-0`, truncate, reserved actions column prevented LAST REGISTRATION → LAST OUTREACH overlap.
3. **Action-first profile reduces Monday friction** — Outreach bar + timeline above registration history matches UJ-5 intent.
4. **Follow-up date bridges Dashboard and Clients** — FR-32 filter chip + dashboard queue merge creates single overdue surface.
5. **Sync sprint-status when epic merges** — Retroactive tracking creates false "next epic" confusion.
