## What worked

1. **Sequential story decomposition** — each story added one surface (gates → overview → health → outbox → paddle → timeline → audits → severity → version) without rewriting the previous contract.
2. **Source-backed truth** — `PlatformKpi` freshness vocabulary stopped synthetic “green” metrics. Missing SHA stayed `missing_instrumentation`.
3. **Security / data minimization** — PlatformAdminOnly + sanitizer + DTO omission tests (no payload, no secrets, no stacks) held through 44.9.
4. **Role separation** — Tenant JWT 403 and RoleExclusivity survived every additive endpoint.
5. **Read-only operational tooling** — diagnostics shipped without requeue, replay, SQL, shell, or Hangfire.
6. **Paddle diagnostic design** — additive `paddle_webhook_deliveries` left idempotency and HTTP retry semantics alone.
7. **TenantIsolation as a merge habit** — new `tenantId` lists got isolation tests in the same PR.
8. **Exact-HEAD review + owner-gated merge** — stories closed only after accepted HEAD, PR CI, merge, and post-merge main CI.
9. **Correction handling** — global light-only (#431 first shape) was refused; Platform-only overlay restored tenant themes without a new story number.
10. **CI vs deploy-readiness** — required CI green was never treated as production cutover.

## What caused churn

1. **Global light-only overshoot** — first #431 deleted tenant ThemeToggle / Appearance / next-themes. Owner corrected scope; rebase waited for 44.9 merge.
2. **Exact-HEAD hold loops** — necessary, but each story needed a separate tracker-close PR after post-merge CI.
3. **Deploy workflow noise** — every main push failed Deploy because Epic 19 host path is blocked. Easy to misread as an Epic 44 regression.
4. **44.9 SHA instrumentation** — truthful `missing_instrumentation` on hosts without `GIT_SHA` is correct and looks like a product gap if deploy wiring is confused with the API contract.

## What should be repeated

- KPI envelope + freshness vocabulary on any new ops metric.
- Negative tests that prove forbidden verbs (Replay, Requeue, Mark Paid, SSH) are absent.
- Isolation tests in the same change as the `tenantId` filter.
- Owner merge authorization with pinned HEAD + CI run id.
- Scope corrections on the same PR, not a fictional follow-on story.

## What should change

- Treat Deploy workflow as Epic 19-owned in dashboards so Epic 44/other closes do not stop to re-prove a known host gap.
- Prefer one tracker-close after post-merge CI rather than mixing closure comments into implementation PRs.
- Keep Platform light-only as a route override; do not reopen a global appearance lock.
