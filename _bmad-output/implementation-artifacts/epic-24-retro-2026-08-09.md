## What went well

- **Incremental epic decomposition** — Each story shippable alone: recovery (24.1) → card signals (24.2) → handoffs (24.3) → list ergonomics (24.4) → docs (24.5). Operators got value after every merge.
- **Clients pattern reuse** — URL-sync filters, `router.replace`, recovery chip visual language, and `activityId` cross-filter matched established Clients module conventions.
- **Brainstorm → build → review loop** — Each story had a brainstorm-intent artifact before implementation; reduced scope drift.
- **Code review caught real UX bugs** — Story 24.4 review surfaced page-reset race, stale grid on overflow, sort select mismatch, and invalid URL param handling; all four patches applied before merge.
- **Story 24.3 review discipline** — Three patches (export filter, activity name, a11y) applied pre-merge.
- **Single compound banner invariant** — Replaced stacked red plan-limit alerts with one recovery-oriented alert; documented in EXPERIENCE.md.
- **Cross-module handoff** — Activity card **Clients (N)** → `/clients?activityId=…` closes the loop between launch catalog and lead queue.

## What we learned

- **Documentation lags multi-story UI epics** — Four implementation stories shipped before EXPERIENCE.md had an Activities section. Story 24.5 as explicit doc story prevents agent/operator confusion.
- **Page local + URL filters need careful reset logic** — Moving filters to URL while keeping page in local state requires filter-change detection to reset page *before* fetch; naive `setPage(1)` in the same handler as `router.replace` causes a stale fetch race.
- **Sort UI presets ≠ full API surface** — Backend accepts all field/direction pairs; UI offers four presets. Document fallback behavior when URL has non-preset combos.
- **Unit tests for ActivityService still touch Redis ctor** — `ListAsync` does not use Redis, but service constructor requires `RedisPublicActivityCache`. Use `abortConnect=false` or future test double to avoid CI flakiness.
- **Invalid URL params should sanitize, not silently coerce** — Bookmarks with typos (`sortBy=registrations`) should clean the URL on load.
- **Public vs admin limit copy must diverge** — PR #123 fixed registrant-facing messages; admin list can show plan context. Keep these surfaces separate in future cap work.
- **Draft brainstorm PRs accumulate** — PRs #117–#126 are artifacts-only; close after merge to reduce noise.

## Key insights

1. **Recovery UX belongs on the list, not billing** — Free a slot never routes to upgrade; published line is primary when dual cap. Operators stay in flow.
2. **URL is the shareable contract** — `/activities?status=published&sortBy=registrationCount&sortDirection=desc` is the operator bookmark pattern.
3. **Card footer is the action surface** — Quick actions (copy, registrations, clients) beat drilling into detail for daily ops.
4. **Docs are a shippable story** — EXPERIENCE.md section prevents drift between code and operator expectations; worth scheduling explicitly in multi-story UI epics.
5. **Review before merge pays off** — Both 24.3 and 24.4 had actionable review findings; zero post-merge hotfixes reported.
