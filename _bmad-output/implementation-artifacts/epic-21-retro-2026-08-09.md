## What went well

- **Mirror-WhatsApp decomposition** — Initiated (21.1) → follow-up + dedup (21.2) → coverage metrics (21.3) matched Platform 0 Epic 5/7 sequencing. Each story shippable alone; operators got profile actions before metrics caught up.
- **Brainstorm-before-build** — 21.2 channel-switch decision (per-channel drafts) and 21.3 shared-helper convergence (Option 2) were decided in brainstorm sessions before implementation, reducing rework.
- **Code review caught real UX gaps** — 21.2: note-aware dirty guard, cross-channel dedup isolation, radiogroup a11y, per-channel drafts on toggle. 21.3: dashboard `ViberFollowUpRecorded`-only test + `withoutOutreach` queue parity test.
- **Shared coverage constant** — `ClientOutreachCoverage.FollowUpCoverageEventTypes` unifies Dashboard, Report, and ClientService; prevents the drift that left metrics WhatsApp-only while the clients list already counted Viber.
- **Parallel integration tests** — Viber dedup mirrors WhatsApp (unit + integration); initiated path has Postgres integration tests.
- **Brand consistency** — `--viber` token and official logo mark (PR #110) integrated with clients queue UX polish (Epic 23 precursor work).

## What we learned

- **Defer coverage explicitly in story files** — 21.2 marked dashboard/report as 21.3 scope; prevented premature predicate edits and kept PR #130 focused.
- **Channel toggle needs draft model, not confirm dialogs** — Sidebar card (21rem) cannot absorb modals; per-channel drafts match independent timeline streams and fixed peek-and-return mis-taps.
- **Metrics and queue filters can diverge silently** — `ClientService.OutreachEventTypes` included Viber from 21.2, but Dashboard/Report predicates did not until 21.3. Single source of truth is mandatory when predicates are copy-pasted.
- **Test asymmetry hides gaps** — 21.3 shipped with ViberInitiated dashboard test but not ViberFollowUpRecorded-only until code review; report had the inverse. Mirror AC wording in test matrix.
- **Pre-existing coverage semantics** — `LeadStatus != New` counts as followed-up without outreach events; `withoutOutreach` ignores lead status. Documented as defer, not introduced by Epic 21.
- **Dashboard cache TTL** — 60s Redis cache on metrics means coverage % may lag briefly after logging outreach; accepted pre-existing behavior.

## Key insights

1. **Multi-channel outreach is three surfaces** — Profile actions, list/queue filters, and aggregate metrics must share one event-type contract or operators see contradictory numbers.
2. **Independent channels need independent drafts** — WhatsApp and Viber are parallel timeline streams; UI state should key by channel, not global form state.
3. **Mirror-WhatsApp is the right v1 strategy** — Deep links + timeline audit + dedup avoids Bot API complexity while delivering operator value in Viber-heavy markets.
4. **Brainstorm “Option 2” paid off** — Shared helper in 21.3 is ~18 lines but prevents a third copy-paste when Telegram or other channels arrive.
5. **Review before merge is established** — Both 21.2 and 21.3 had actionable patches; zero post-merge hotfixes reported for merged work.
