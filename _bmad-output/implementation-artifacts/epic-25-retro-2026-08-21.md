## What went well

- **Shared resolver spine** — `RegistrationThemeResolver` + `RegistrationThemeQueries` centralize resolution for admin API, public door, and confirmation emails; follow-up email fix (#198) reused the same path.
- **Community → activity inheritance model** — `inheritCommunityBrand` default true matches operator mental model; Design tab preview respects draft inherit flag after CR patch.
- **Preset renderer separation** — Four layout presets isolated in web components; admin preview mirrors public without duplicating business rules.
- **Code review caught real bugs** — Community rename wiping brand kit, section_header in answer normalization, missing backend label validation — all patched before or during review follow-up.
- **Incremental polish PRs** — Dark-mode preview, layout stretch, publish gate, and email hero each shipped as focused fixes without reopening the epic scope.

## What we learned

- **Sprint-status lag hurts orientation** — Epic 25 stayed in `review` for over a week after merge; `bmad-next` and retros depend on synced tracking.
- **Theme resolution has three surfaces** — Admin preview, public registration, and transactional email must all call the same resolver; email was easy to miss (fixed in #198).
- **Legacy hero/accent on Overview tab** — Intentionally moved to Design tab + theme JSON; operators need clear UX copy during transition (deferred doc note).
- **In-memory DB tests must respect tenant filter** — `RegistrationThemeQueriesTests` used random `TenantId`; EF global filter defaults to `TenantIds.Default`, so community lookup returned null. Fixed 2026-08-21.
- **Community brand cache invalidation deferred** — Updating community kit does not invalidate public activity Redis cache; inherited theme may lag until activity refresh (acceptable v1, track for scale).

## Challenges and growth areas

- **Stories stuck in `review` after merge** — Workflow gap between code review approval and sprint-status `done`.
- **Operator UAT not formally signed off** — Local Docker verification assumed; no recorded operator checklist for Design tab + public presets.
- **Deferred CR items remain open** — Logo asset tenant ownership on public URLs, community kit cache invalidation, server-side contrast on inherited accent.
- **Pre-existing CI failure masked** — `RegistrationThemeQueriesTests` failed on main since Epic 25; caught in Epic 28 CR, fixed in this retro pass.

## Key insights

1. **One resolver, many touchpoints** — Any new registration surface (SMS, calendar, embed) must consume `RegistrationThemeQueries`, not re-resolve fields.
2. **Design tab is the branding home** — Overview hero/accent retirement is correct but needs operator guidance.
3. **Review + follow-up PR pattern works** — Epic-sized PR (#182) plus small polish PRs (#191–#198) kept main stable.
4. **Test tenant context matters** — Infrastructure tests using in-memory EF must align `TenantId` with `TenantFilterTenantId` (defaults to Platform 0).
5. **Sync sprint-status at epic close** — Prevents `bmad-next` from routing to stale `review` stories.
