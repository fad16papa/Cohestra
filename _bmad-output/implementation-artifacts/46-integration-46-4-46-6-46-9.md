## Why this PR exists

The three stories were independently green on the same baseline. Sequential GitHub merge would fail:

- `ProductionSecurityValidator` and its tests conflict between 46.4 and 46.9
- CI workflow steps conflict between 46.4 and 46.9
- 46.4's isolated ownership freeze would reject intentional 46.6/46.9 files after the first merge

## Resolutions

1. Dedicated Production plane keeps 46.4 fail-closed isolation (Redis password, apex URL, SendGrid independence, seed lock, blank leftover CORS slots).
2. Non-Development hosts keep 46.9 CORS, recaptcha, JWT length, and non-UAT Redis password checks.
3. PlatformAdmin seed is allowed only on a UAT public host (46.4 one-shot). It is refused on dedicated Production and on non-UAT Production.
4. `/ready` remains `postgres`, `redis`, `default-tenant`. OTel registers beside existing infrastructure.
5. `GlobalExceptionHandler` returns 503 for auth session-store outage, then records unhandled exceptions for OTel.
6. CI keeps 46.4 runtime-secrets isolation plus 46.9 CSP, tenant-filter allowlist, and secret-inventory contracts.
7. Isolated 46.4 ownership freeze retires only when both 46.6 and 46.9 story files are present. Other provenance gates stay on.
8. Public registration is an explicit owner pair. Compose requires `SelfServeSignup__RegistrationClosed` and `SelfServeSignup__Recaptcha__Enabled`. Open + disabled is refused. Bypass is compose-locked empty. No Production credentials are created.
