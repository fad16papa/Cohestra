06

Disney Method

Dream the clubhouse, engineer the hinges, stress-test the locks.

Dreamer

  • Ops types cohestra.app/platform/login in muscle memory like /admin on WordPress
  • Clubs never learn that URL exists unless they guess
  • Same password field, same a11y, zero second design system for a door
  • Future custom domains inherit tenant /login automatically — same page

Realist

  • Implement helper + middleware + form audience + guard + tests + docs
  • Middleware before static short-circuit; matcher covers all paths
  • Next origin behind nginx uses Host; tenant.localhost:8088 is detectable
  • Platform login outside (platform) group so unauthenticated users can render on apex
  • After tenant-host redirect, platform login is apex and fetchPublicDoor is marketing

Critic

  • Redirect loops if apex misdetected as slug — parseTenantSlugFromHostname returns null on localhost and cohestra.app
  • www.cohestra.app is apex; do not treat www as tenant
  • default.localhost is a tenant; must redirect
  • Keep smoke on apex if PUBLIC_BASE_URL is a tenant host in CI
  • Leaking PLATFORM_LOGIN_PATH in operator error CTA is acceptable — user proved platform account
  • Do not leak it on the empty operator form
  • Platform login Operator sign-in link is fine — escape hatch for ops who missed the path
  • No API audience: crafted POST from /login still authenticates PlatformAdmin — UI door is product truth; JWT policies are security boundary
  • Do not 404 /platform on tenant hosts if we can 307 — friendlier for mistyped bookmarks
  • Extracting later remains possible; this does not burn the bridge
Synthesis

Two honest doors

The split was solving an origin/blast-radius fear; the real job is two honest doors. Path /platform/login on apex + shared /login on every tenant host does that without a second Next app.
Host and path are orthogonal: Host = which tenant (or apex); path = which audience door. Mixing them — ops UI on a club host — is the bug to prevent.
Tenant login must stay one page module so apex and slug never drift. Platform login may share LoginForm but not tenant branding, register, or reset.
UI audience checks are product truth; API role policies are the security boundary. Do both. Do not add a login audience DTO.
Door A
/login

On apex and {slug} hosts — all tenants and TenantAdmins. Same page. Host branding only.

Door B
/platform/login

On marketing/apex hosts only — PlatformAdmin / Cohestra ops. noindex. No register. No reset. No tenant chrome.

  • Tenant slug hosts requesting /platform or /platform/login → 307 to apex equivalent
  • Operator form rejects PlatformAdmin (CTA to /platform/login). Platform form rejects non-PlatformAdmin (CTA to /login)
  • Admin shell bounces PlatformAdmin to /platform. Platform shell bounces others to /dashboard
  • No new API, no new compose service, no platform link on default tenant login footer
  • Implement Ship-in-60-minutes slice: helpers, middleware redirect, login-form symmetry, admin guard, tests, README + launch checklist

Killed · superseded

  • web-1/web-2 extract
  • platform.{apex} origin
  • packages/auth-client split
  • Path doors in the existing web app replace all of the above
