A document vs a person

Tally is a blank page that emits rows. Cohestra is a Saturday session that emits a client. Brainstorm, 27 Aug 2026 — steal the page, keep the person.

Two products

Tally.so

  • Slash to insert. Logic free. Stripe free. Embed free.
  • Guest list = Sheet / Notion.
  • Wins the first form.

Cohestra

  • Activity → field list → Client + Registration.
  • Dedup, capacity, QR, campaigns.
  • Wins the second event — if they started here.

SCAMPER — what to steal

  • Substitute the type dropdown with / insert.
  • Combine identity + consent as optional steps, not a wizard religion.
  • Adapt hidden fields so WhatsApp links carry ?ref=.
  • Modify FormFieldEditor, do not add a canvas (UX-DR32).
  • Put-to-other-use: website contact still creates a Client.
  • Eliminate the reason to wrap Cohestra in a Tally embed: native embed later.
  • Reverse: Tally cannot become our CRM; stop competing on NPS blocks.

First principles

  • A form without a person is a CSV.
  • A person without an event is a newsletter tool.
  • Publish still requires phone or email.
  • Field id is the contract, labels are decoration.
  • Show/hide is a recipe, not a programming language.

Failure modes

  • We ship matrices and become a worse Tally.
  • We webhook Tally forever and never own capture.
  • visibleWhen grows nested AND/OR in sprint 2.
  • Embed XSS on tenant sites.
  • Drafts without GDPR language.
If they still need Tally to find out who’s coming, we don’t have a form problem — we have a product-entry problem.

Chosen

Slice A: hidden, textarea, date, piping, closed copy, slash-add, operator notify. Slice B: recipes + optional steps. Slice C: embed + website contact. Kill: clone Tally, logic IDE, in-form Stripe.
