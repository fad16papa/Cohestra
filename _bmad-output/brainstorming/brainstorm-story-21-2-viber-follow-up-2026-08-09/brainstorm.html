Viber Follow-Up — Brainstorm Synthesis

How to give Viber the same outreach audit trail WhatsApp already has — without cluttering the client profile sidebar.

The gap

21.1 opens Viber and logs ViberInitiated. The Log outreach card still saves only whatsapp_follow_up_recorded. Operators who prefer Viber have no in-app record of outcomes.

Technique — First principles

Mirror at the API layer

  • ViberFollowUpRecorded + POST .../viber-follow-up
  • 15-minute dedup on identical status + note → 409
  • Same status vocabulary: Contacted · Awaiting reply

Technique — SCAMPER (UI placement)

Modify the existing card — channel toggle

One sidebar card. Toggle picks which timeline stream receives the save. Baseline/dirty guard is per channel.

Rejected: second Viber-only card

EXPERIENCE.md locks sidebar to Next follow-up + Log outreach — two log cards breaks the layout contract.

Rejected: invisible auto-route

Save-to-last-initiated feels magic when operator WhatsApp'd Monday and Vibers Tuesday.

Technique — Failure modes

  • Duplicate save within 15 min → toast with API message (same as WhatsApp)
  • Switch channel mid-edit → reset note; status dropdown persists
  • No initiated events yet → default WhatsApp; operator can still pick Viber manually

Operator flow (UJ-5 Viber path)

Open Viber on row → Profile → Toggle Viber → Awaiting reply + note → Save outreach log → Timeline: Viber follow-up recorded

Verdict

Ship: Full WhatsApp mirror in backend + channel toggle on ClientOutreachLogCard.

Defer to 21.3: Dashboard coverage, list Last outreach column, report predicates.
