The People of the Paying Operator v. billing=success

A keepsake from the Paddle return-trust session. Not minutes. A trial held inside a URL bar, with a thermal receipt as the exhibit table.

Count I Whether Cohestra’s slug-free marketing apex — /billing/paddle-return hopping to {slug}.cohestra.app — is safe to ship in production.
Count II Whether trusting the browser, the client, or a query string undermines billing truth.
Count III Whether a paying operator can feel the transaction is legit — not merely that the servers believe it.
Paddle checkout chrome → cohestra.app/billing/paddle-return → {slug}.cohestra.app

Money and plan state are granted only by HMAC webhooks and authenticated Paddle sync — never by _ptxn, never by billing=success. That was the assumption walking into the room. The room then asked whether the hop still lies even when the money does not.

Six Thinking Hats

Exhibit A · colored depositions

White · sworn facts

  • Paddle allows one Default payment link per environment. It cannot be {slug}.cohestra.app.
  • The return page is anonymous. It maps txn_ to a tenant dashboard URL built server-side from PublicWeb.BaseUrl.
  • custom_data.tenant_id is written by our API with the server API key, not by the browser.
  • Plan unlock on the dashboard calls authenticated SyncFromProvider, which re-fetches the transaction from Paddle and rejects a tenant_id mismatch.
  • HMAC-signed webhooks remain the durable source of truth. The return hop is a locator plus a refresh nudge.
  • Overlay onCompleted navigates to the current tenant origin, bypassing the apex hop when JavaScript works.
  • The resolver does not check transaction.status before appending billing=success.
  • The client follows whatever http(s) redirectUrl the API JSON returns after a same-origin fetch.
  • txn_ IDs are high-entropy. They are not a login cookie. They do not mint a JWT.
  • Production hop is cohestra.app → {slug}.cohestra.app. Local hop is localhost → {slug}.localhost.

Red · the pulse after the card

The operator just typed a card. Any extra domain in the URL bar feels like a bait-and-switch.

“Returning to your workspace” with no receipt, no amount, no plan name feels hollow after paying $29.99.

An SSL error on https://localhost already taught this operator that a return URL can lie. That scar transfers to production.

A marketing-styled apex page after Paddle’s checkout chrome feels like leaving the bank for a flyer.

If the dashboard still says Basic for two seconds, the operator believes the charge failed.

PH and SG operators already distrust payment rails. A hop through a different host confirms the fear.

Yellow · why the hop exists at all

  • One approved apex domain is how Paddle designed Checkout. Fighting it with per-slug successUrls will keep failing approval.
  • A server-built tenant URL means the browser cannot pick a victim workspace.
  • The same pattern works in sandbox HTTP, nip.io, and live HTTPS without changing Paddle settings per tenant.
  • Overlay successUrl on the apex matches Paddle’s approved domain so they stop dumping people on /pricing.
  • The webhook can land before the redirect. The hop is then just a courtesy door.

Black · objections entered

  • billing=success on a draft or canceled txn trains a false success toast.
  • Anyone with a leaked txn_ can discover the tenant slug via the redirect Location.
  • Anonymous GET is a txn-oracle: 200 versus 404 enumerates whether a transaction exists.
  • If custom_data.tenant_id is missing, sync may ApplyTransaction onto the logged-in tenant.
  • Client isHttpUrl is javascript-free and still trusts API JSON. A compromised or HTTP-downgraded API becomes an open redirect.
  • Referrer on the apex page can leak _ptxn to third-party marketing scripts.
  • Rate-unlimited Paddle GetTransaction from our API burns quota and can be used as a proxy.
  • The cross-site hop drops HttpOnly cookies. The operator may land on login and think payment vanished.
  • Paddle website approval of cohestra.app does not automatically bless every {slug} unless Paddle treats eTLD+1 as one site.

Green · remedies the court may order

  • Only redirect when Paddle status is completed, billed, or paid. Otherwise show pending copy.
  • Server 302 from the API with no JSON client hop — one fewer trust surface.
  • Sign the return URL (HMAC of tenant + txn + exp) so the dashboard ignores unsigned billing=success.
  • Put the return page on a dedicated billing.cohestra.app with no marketing trackers.
  • Show plan name, trial days, and last4 on the apex handoff screen before redirect.
  • Keep the operator on the tenant host the whole time via overlay onCompleted. Treat apex as hosted-checkout fallback only.
  • Require a completed webhook before showing success. Poll a public status token instead of txn lookup.

Blue · the judge’s notebook, already

  • Separate three layers in every review: money truth, navigation locator, and felt receipt.
  • Production UAT must screenshot the URL bar at Paddle, apex, and slug host. Trust lives there.
  • Never call the query param a session that grants a plan. Name it checkout_return_ref.

Devil’s Advocate Courtroom

All rise · the hop on trial

The Court of the Address Bar is now in session

Prosecution

You ship an anonymous txn oracle that maps payment IDs to club URLs. That is a customer directory.

billing=success is theater. The code does not ask Paddle if the card actually captured.

Client-side window.location.replace of API JSON is classic open-redirect packaging.

You already burned trust with https://localhost. Repeating a hop in production repeats the trauma.

A PH-registered, SG-operated entity chose Paddle as merchant of record so the charge is supposed to look official. A marketing interstitial undoes MoR gravity.

Defense

The browser never chooses the tenant. Paddle custom_data plus our DB slug does.

SyncFromProvider refuses a txn whose tenant_id is not the JWT tenant.

No JWT is issued from _ptxn. Worst case of a leaked txn is a login wall on the right club.

Paddle itself appends _ptxn to the default payment link. We did not invent client-visible txn IDs.

HMAC webhooks still fire if the operator closes the tab. Money truth does not need the hop.

Jury. Safe enough to ship for money. Not safe enough to claim the hop is a trusted receipt.
Convict the success query string
Acquit the apex domain

Verdict condition: gate redirect on completed or billed, pin redirect host to *.cohestra.app, no third-party scripts on the return page.

Sentence: Keep the architecture. Strip the lie. Add a receipt beat.

The triplicate

Synthesis · peel the layers

Click a sheet to bring it forward. Three truths. Only one of them is money.

Layer 1 · carbon yellow MONEY TRUTH

HMAC webhook plus authenticated Paddle GET. Not the client. Not the query string. Not the toast.

The bank still fires if the operator closes the tab. This layer was never on trial. It is granted.

Ship this as if the hop did not exist — because for money, it must not exist.

Layer 2 · carbon pink NAVIGATION LOCATOR

Apex /billing/paddle-return is the right production shape. Paddle will not bless a per-slug success URL.

The jury acquitted the domain choice. The browser never picks the tenant. Server-built URL. Overlay stays on the slug host when JS works. Apex is the hosted-checkout refugee door.

Pin the destination to the host builder. Same-registrable-domain hop, https to https, never mixed schemes.

Layer 3 · original FELT RECEIPT

Currently too weak, because billing=success is unearned. Trusting the client does not grant a plan today — it grants a success story. That story can be false.

False success is the production trust bug. Not the slug-free domain.

The operator needs the URL-bar family they logged into, the workspace spoken aloud, a plan badge that matches Paddle, and an invoice they do not have to hunt.

What the three layers say when stacked

Trusting the client does not grant a plan today, but it does grant a success story. That story can be false. False success is the production trust bug, not the slug-free domain.

The hop may be a courtesy door. It must never be a receipt. Convict the query string. Keep the architecture. Strip the lie. Add a receipt beat.

Chosen direction

  • Keep apex /billing/paddle-return.
  • Gate redirect on completed or billed.
  • Pin destination to our host builder.
  • Silent return page — no marketing trackers, treat _ptxn like a password.
  • Overlay stays on the tenant host.
  • Never auto-login from txn.

Ship condition for “feels legit”: the URL bar family matches the login host after at most one same-registrable-domain hop; the workspace name is spoken aloud; the plan badge matches Paddle; the invoice is visible without hunting.
